## Summary

**What changes in 0.5.0**

1. **One store per machine**: `~/.local/state/herdr-job-board/board.json` (XDG state dir), not
   `.git/job-board.json`. Every card carries a `project` (from the git common dir, so worktrees
   count as their repo; outside git, the folder, or `home` for `~`). Ids stay whole numbers and
   are unique across projects.
2. **Each card remembers its coordinator** (`origin`: the pane that wrote it). An answer button
   goes to the card's coordinator, not to whoever opened the pane. If that pane is gone, the
   board says so and offers the board's own coordinator instead (a second press sends there).
3. **The pane shows every project** with a short coloured tag on each row (`sfc`, `ai`,
   `herdr`, `home`); `p` steps through projects, `P` goes back to all; a filtered view still
   counts what it hides ("+1 other").
4. **One-time import** (`board.mjs import`) of the per-repo boards: sfc-integration's 192 cards
   keep their ids (1 to 211); ai-config's one card (`1 fix-x`, a leftover test from 13 Oct with a
   `/tmp` report) clashes with sfc's id 1 and is dropped by default (or renumbered to 212). Old
   files are renamed `job-board.migrated.json` and backed up.
5. **Card 207 folded in**: `board.mjs setup` writes the key binding (`prefix+b` →
   `herdr-job-board.open`) and the `$board` sidebar row into Herdr's `config.toml`, with a
   backup, idempotently; `doctor` points to it. Each workspace's sidebar shows **its own** cards'
   counts; the board's title line shows the total.
6. **CLI scope**: `ls`, `json` and the Claude hooks show **your cards** (this project's, plus any
   card you, this coordinator pane, own) by default; `--project <name>` or `--project all`
   widens it. Writes to a card of another project that you don't own need `--project <its
   project>`, so a remembered old id can't silently change another project's card.
7. **New commands**: `import`, `projects`, `project set`, `retag`, `adopt`, `answer` (the
   Telegram path: same delivery as a button), `setup`, `contract`, `guide`, `export --legacy`
   (rollback).
8. **Telegram**: one bot, one **front** coordinator holding it. A reply such as `170 go` becomes
   `board.mjs answer 170 go`, which delivers it to card 170's coordinator exactly like a
   button. Outbound pings for new Waiting cards through an optional `notify` command
   (`tg-notify.sh`), off by default.
9. **Where the coordinator lives**: stay in sfc-integration through 0.5.0 (it becomes the front
   and holds Telegram, as today). Move to a small **`~/work` git repo** after guard v5 lands (it
   must protect every job repo, not only the coordinator's own). Details in section 7.

## 1. Store

### Location
- **`${XDG_STATE_HOME:-$HOME/.local/state}/herdr-job-board/board.json`**, overridable with
  `JOB_BOARD_HOME` (a folder) or `JOB_BOARD_FILE` (a file, as today, for tests and for anyone
  who wants a separate board).
- Not the plugin folder: `herdr plugin install` rewrites it in place.
- Not `$HERDR_PLUGIN_STATE_DIR`: Herdr sets it only for plugin actions; the coordinator's CLI,
  the hooks and the board pane (started by `herdr pane run` in a plain shell) don't get it. Today
  `stateDir()` prefers it, which is fine for `restart.log` but would split the board in two. The
  store gets its own resolver that ignores it; `doctor` notes when the variable is set to
  another folder.
- One store per machine (the LXC and the Mac each have their own). No sync.

Folder layout:
```
~/.local/state/herdr-job-board/
  board.json            the board (0600)
  board.json.lock/      the write lock (as today)
  archive/2026-10.jsonl Done cards older than 7 days, one JSON line each
  backups/              board-2026-10-19.json (first write each day, 7 kept),
                        import-<ts>/<repo>.json (each imported file, kept)
  turns/<session>.json  the Stop hook's turn records (was .git/job-board.turns/)
  restart.log           as today
```

### Schema (version 2)
```json
{
  "version": 2,
  "next_id": 212,
  "front": "w4:p6",
  "projects": {
    "sfc-integration": { "tag": "sfc", "color": "magenta", "root": "/root/sfc-integration",
                         "git": "/root/sfc-integration/.git", "workspace": "w4" },
    "herdr-job-board": { "tag": "herdr", "color": "cyan", "root": "/root/herdr-job-board",
                         "git": "/root/herdr-job-board/.git", "workspace": "" },
    "home":            { "tag": "home", "color": "blue", "root": "/root", "git": "" }
  },
  "coordinators": { "w4:p6": { "workspace": "w4", "project": "sfc-integration", "seen": "…" } },
  "items": [
    { "id": 211, "project": "herdr-job-board", "origin": "w4:p6", "workspace": "w4",
      "title": "Job board 0.5.0, one board for all projects: plan", "column": "doing",
      "job": "board-v5-plan", "…": "the 0.4 fields, unchanged" }
  ],
  "panes": { "w4:t1": { "pane": "w4:p14", "origin": "w4:p6" } },
  "reports": { "6b722c47701fe0ea": { "id": 1, "at": "…" } },
  "imports": [ { "from": "/root/sfc-integration/.git/job-board.json", "at": "…", "renumbered": {} } ]
}
```

- **Project identity**: `git rev-parse --path-format=absolute --git-common-dir` from the cwd,
  realpath'd. Worktrees (`/root/sfc-integration-wt-usage-redesign`) share it, so they map to
  their repo. The name is the main worktree's folder name (`dirname` of a `.git` common dir; a
  bare repo's own name). Two repos with the same folder name: the second gets `<parent>-<name>`.
  Outside git: `$HOME` (and anything under it that isn't a repo) is `home`; another folder is its
  own project named after it, keyed by its realpath.
- **`tag`** (shown on rows): assigned once, when the project is first seen: the name's first
  hyphen segment cut to 7 characters (`sfc`, `herdr`, `ai`, `release`), extended with the next segment's initial on a clash (`sfc` stays sfc-integration's; a later
  sfc-app-track gets `sfc-a`). First come keeps the short tag. `project set <name> --tag rnm`
  changes it. At most 7 characters.
- **`color`**: one of 6 from the terminal's 16-colour palette, assigned in turn: magenta, cyan,
  blue, green, bright magenta, bright cyan. Not yellow or red (they mean urgency). Colour is never
  the only sign: the tag is text.
- **Card fields added**: `project` (required in v2), `origin` (the coordinator pane that owns
  it; empty for cards nobody owns), `workspace` (the Herdr workspace its job runs in, so the live
  status looks the agent up by name in the right workspace; 0.4 used the pane's own workspace).
- **`coordinators`**: every write from a coordinator (role unset or `coordinator`, inside Herdr)
  records its pane, workspace, cwd project and time. Used to route and to say "sfc coordinator".
- **`front`**: the coordinator that gets answers no one else can take (and holds Telegram).
  `board.mjs front` sets it to the calling pane; default: the pane that last ran `open`.
- **`reports`**: the `reported` hashes `job-report` has applied, with the card id, kept 30
  days. Without it, archiving a Done card would make a repeat `job-report --if-final` (the wait
  script firing again) add a second card.

### Locking with several coordinators
- Keep the 0.4 lock (`mkdir board.json.lock`, owner `pid host random`, stale only when the owner
  is gone, atomic temp-file rename). It is per file, so one lock now covers every project.
- Contention stays low: a write is read-parse-change-write of ~100 to 300 KB, a few ms. Writers:
  each coordinator's CLI, `wait-agent-report.sh` (through `job-report`), the board pane's `sent`
  notes and `panes`. The 10 s wait is far above what that needs.
- Reads take no lock (readers see a whole file thanks to the rename), as today.
- Test with 4 concurrent writers × 200 adds, no card lost, ids unique (the existing lock tests
  run with 2).

### Id allocation
- Global `next_id`, as today, under the lock. Never reused, even after an archive.
- Import keeps an id when it is free and renumbers from `next_id` when it isn't (section 2).

### Done retention and archiving
- 0.4 drops Done cards after 14 days. sfc-integration finished 177 cards in 6 days (13 to 19
  Oct), about 30 a day; with several projects that is 500+ cards and 300 KB in two weeks.
- 0.5: Done cards older than **7 days** move (inside the same locked write) to
  `archive/YYYY-MM.jsonl`, one line each, appended. The board's Done section shows today's, as
  before; `ls --done 30d` and `json --archive 2026-10` read the archive. Archives are kept; a
  month is roughly 1 MB.

### Backups
- Before the first write of each day: copy `board.json` to `backups/board-YYYY-MM-DD.json`,
  keep 7.
- `import` copies each source file to `backups/import-<ts>/` before touching anything.
- `board.mjs restore <backup>` puts a backup back (under the lock; the current file goes to
  `backups/` first).

## 2. Migration

`board.mjs import [--dry-run] [--keep-stale] [<file>…]`

- With no files: the cwd's repo board, plus every `$HOME/*/.git/job-board.json` and
  `$HOME/*/*/.git/job-board.json`. On this machine that is two:
  - `/root/sfc-integration/.git/job-board.json`: 192 cards (177 done, 10 to do, 4 waiting,
    1 doing), ids 1 to 211, `next_id` 212, 110 KB.
  - `/root/ai-config/.git/job-board.json`: 1 card, `1 fix-x`, waiting since 15 Oct, report in
    `/tmp/job-scripts-PKnppc/` (a test run of the skill's scripts). No other repo under `/root`
    has a board.
- **Order**: the biggest board first, so the most ids stay. Each card gets the source repo's
  project, `origin` = the pane running the import when it is that repo's coordinator (else
  empty), and `workspace` = the Herdr workspace whose label is the project name (`w4` is
  labelled `sfc-integration`), else empty.
- **Ids**: kept when free; otherwise renumbered from `next_id`. The map is printed, stored under
  `imports[].renumbered`, and the card gets `was: "ai-config#1"` so `json` shows it.
- **Stale cards**: a Waiting card whose job report is in `/tmp` and missing, and that is older
  than 3 days, is listed and left out unless `--keep-stale`. On this machine: only `fix-x`.
- **Re-tag proposals**: the preview lists open cards whose title names another known project or
  whose job ran in another repo's worktree (from the agent list, when still running), with a
  suggested project. For sfc-integration's open cards:

  | Card | Title | Proposed |
  |---|---|---|
  | 200 | 3CX SSL certificate: renew before ~25 Oct 2026 | home |
  | 204 | Git access on the LXC: narrower tokens instead of Touch-ID: pick | ai-config |
  | 206 | Job board 0.4.0 follow-ups in ai-config and the job skill | ai-config |
  | 207 | Board key binding + sidebar count (in 0.5.0) | herdr-job-board |
  | 209 | Coordinator auto-restart supervisor (parked) | ai-config |
  | 211 | Job board 0.5.0, one board for all projects: plan | herdr-job-board |

  `import --retag 200=home,204=ai-config,…` applies them; `retag <id> <project>` works later.
- **Dry run first** (`--dry-run` prints exactly what happens, writes nothing):
  ```
  import: 2 boards, 193 cards
    /root/sfc-integration/.git/job-board.json   192 cards, ids kept (1–211)
    /root/ai-config/.git/job-board.json           1 card
        1 fix-x  waiting since 15 Oct, report gone (/tmp/job-scripts-PKnppc/r.json): left out
                 (--keep-stale imports it as 212)
  re-tag (from titles; apply with --retag): 200→home 204→ai-config 206→ai-config
         207→herdr-job-board 209→ai-config 211→herdr-job-board
  then:  board.json 192 cards, next_id 212; old files renamed *.migrated.json; backups in
         ~/.local/state/herdr-job-board/backups/import-20261019-1215/
  ```
- **Old files**: renamed to `job-board.migrated.json` beside the original (same folder, so a
  rollback is one `mv`), after the copy in `backups/`. Not left in place read-only: the user runs
  as root, and root ignores file modes, so a 0.4 CLI would keep writing a "read-only" file. A
  0.5 CLI never reads `.git/job-board.json` again, except `import`.
- **Automatic import**: when `board.json` doesn't exist yet and a 0.5 command runs in a repo
  that has a legacy board, the CLI imports that one repo with no renumbering needed (an empty
  store) and says so once. Later boards need the explicit `import` (they may clash).
- **Stray legacy writes**: `doctor` warns when a `.git/job-board.json` reappears after the
  import (a 0.4 copy still running somewhere) and offers `import` again: it merges by id and
  `updated` time.
- **Rollback**:
  1. `board.mjs export --legacy --project sfc-integration > /root/sfc-integration/.git/job-board.json`
     writes that project's cards in the v1 format (ids are already unique, so they are valid);
     or, to go back to the moment of the import, `mv job-board.migrated.json job-board.json`.
  2. Install 0.4.0 again (`herdr plugin link` a checkout at tag v0.4.0, since Herdr 0.9.3 has no
     ref on `plugin install`; then `restart`).
  Cards written after the import are only in `board.json` unless exported.

## 3. Coordinator routing

### Who owns a card
- `origin` is set when a coordinator creates the card (`add`, `job-start`, `job-report` run
  from its background wait, which inherits its `HERDR_PANE_ID`), and only when the writer is a
  coordinator (role variable unset or `coordinator`, `HERDR_ENV=1`). Workers and the pane never
  set it.
- It changes only through `adopt` (`board.mjs adopt <id>…`, or `adopt --project P --gone`: every
  open card of P whose owner pane is gone), or when the owner is gone and another coordinator
  edits or moves the card (it takes it over and the CLI says so).
- The project and the owner are separate: card 211 is a herdr-job-board card owned by the
  sfc-integration coordinator, as happens today.

### Sending an answer (button, `answer`, Telegram)
1. The card's `origin`, when Herdr's agent list (the pane already fetches it every 3 s) shows an
   agent in that pane.
2. Else the project's live coordinator (the newest `coordinators` entry for that project still
   in the agent list).
3. Else the `front` coordinator, but **only after a second press**: the card says
   `no ai-config coordinator is running: press Go again to send it to the board's coordinator
   (sfc, pane w4:p6)` (mockup D). Sending another project's answer somewhere new is the user's
   choice.
4. Else `couldn't send: no coordinator is running for ai-config; start one there, or use Other…`.
   Other… switches to the card's workspace.

The card shows where it went: `sent: Go · 12:03 · to sfc coordinator (w4:p6)`.

### The text
`Board card <id> (<tag> · <title>): <label>`, e.g.
`Board card 170 (sfc · magicwan v343 fleet rollout: approve the waves): Go`. Same shape as 0.4
(the id first, a whole number; title and label cleaned), so a 0.4-era coordinator still parses
it. From Telegram: `… : LON only first (from Telegram)`.

### Several coordinators at once
Each sees its own cards in `ls` and its reminder; each answer goes to the card's owner; the pane
shows everything. Sidebar tokens are per workspace (section 4). No coordinator ever receives
another one's answer without the second press above.

### The Claude hooks
- **UserPromptSubmit reminder**: the Waiting cards in scope "mine" (this project + cards this
  pane owns), at most 8, then one count line: `+3 waiting in other projects (not yours; the
  board shows them)`. Not all projects: another coordinator's cards are not this one's to close.
- **Stop check**: `waitingTouched` counts only cards in scope "mine". In 0.4 any Waiting change
  counted; with one board, another coordinator's write during the turn would wrongly satisfy it.
- **Ownership check on writes**: `move`, `done`, `edit`, `rm` on a card of another project
  that this pane doesn't own are refused (exit 2) with
  `card 1 belongs to sfc-integration (owner w4:p6); add --project sfc-integration to change it`.
  This stops the classic migration slip (an ai-config coordinator typing `done 1` meaning its old
  card 1). It doesn't block the common case: the sfc coordinator managing herdr-job-board cards
  it created.
- Turn records move to `turns/` in the state folder; same 7-day cleanup.

## 4. Pane UI

- **Default: all projects.** The title line counts all: `Job board · all projects · 4 need you`.
- **Project strip** (line 2, inbox and wide; compact shortens it): every project with open cards,
  with its "need you" count: `Projects: ▸all  sfc 3  ai 1  herdr  home`. A click on a name
  filters; a click on `all` clears.
- **Row**: `▸108 ! sfc   UI consistency plan: answer 10 questions          3 days`. The tag
  column is as wide as the longest tag on screen (at most 7, 4 in compact) plus one space, in the
  project's colour. The id and age are never cut (as in 0.4); the title gives way.
- **Open card**: the first line names the project in full (`sfc-integration · …`), and a
  Waiting card with buttons ends with where answers go (`answers go to: sfc coordinator (pane
  w4:p6)`), or the warning when no coordinator is live.
- **`p`**: next project with open cards (in strip order); `P`: back to all. The filter is the
  pane's own (not written to the board), starts at all, and holds until the pane closes.
- **Filtered**: title `Job board · sfc-integration · 3 need you (+1 in other projects)`; each
  section header counts what it hides (`WAITING ON YOU (3 · +1 other)`), so nothing is hidden
  without a count. Blocked agents of other projects still show under Waiting with their tag:
  a blocked job needs you whatever the filter. (Suggested; alternative is to count them only.)
- **Wide (≥ 120)**: as 0.4 (Waiting two cards a row, Doing | To do columns); the tag sits after
  the id in each card's title line and in each row.
- **Ordering**: Waiting as today (blocked agents first, then by id). Not grouped by project:
  the tag is enough, and grouping costs a header line per project in a short pane.
- `ls` gets `--project`, and draws the same.

## 5. CLI and skill contract

| Command | 0.5.0 |
|---|---|
| `add` | `--project P` (default: the cwd's project); sets `origin` and `workspace` |
| `move` / `done` / `edit` / `rm` | ids are global; ownership check (section 3); `--project` to change a card you don't own |
| `retag <id> <project>` | new: change a card's project |
| `job-start <slug>` | new `--worktree <path>`: the project from that worktree (the skill passes it); else `--project`, else the cwd's. Records `workspace` = `$HERDR_WORKSPACE_ID` |
| `job-report <slug>` | finds the job's card among this pane's cards first, then this workspace's, then any; an ambiguous slug (same slug open in two projects) is an error listing both ids; uses `reports` for repeats |
| `ls` | scope "mine" by default; `--project P` / `--project all`; `--done 30d` |
| `json` | same scope; prints `{version: 2, items, projects}`, so callers reading `.items` keep working; `--project all` prints the whole file; `--archive YYYY-MM` |
| `answer <id> <text>` | new: deliver like a button press (routing above), mark `sent`; `--from telegram`. Refused for workers (role variable set to anything but coordinator) |
| `adopt`, `front` | new: take over cards; set the front coordinator |
| `projects`, `project set <name> [--tag T] [--color C] [--name N]` | new: list (tag, colour, root, open counts, owner pane alive or not), rename, re-tag |
| `import`, `export --legacy`, `restore` | new: section 2 |
| `setup [--dry-run] [--key K] [--no-key] [--no-sidebar] [--no-reload]` | new: section 4 below |
| `contract` | new: `{"version":"0.5.0","contract":2,"commands":[…],"flags":{…},"hooks":["UserPromptSubmit","Stop"],"store":"global"}` |
| `guide` | new: the agent instructions (find the CLI, scope, writing cards, buttons, answers, Telegram, job-start/report), the one source the skill and the README use |
| `path` | the store's path |
| `open` | unchanged for the user; the pane's `--origin` becomes the fallback for cards with no live owner |

**Backward compatibility (0.4.x callers)**
- Every 0.4 command and flag keeps working. A 0.4 skill calling `job-start` without `--worktree`
  gets the coordinator's cwd project (wrong for cross-repo jobs, harmless; `retag` fixes it).
- `json` still has `.items`; ids are still whole numbers; the button text still starts
  `Board card <id> (`.
- `JOB_BOARD_FILE` pointing at a v1 file: read as v1 (every card gets the file's project) and
  written back as v2 on the first write.
- `contract` tells the skill which it has: no `contract` command (exit 2) means 0.4, contract 1.

**Job skill changes (ai-config, a separate PR after 0.5.0 ships)**
- `scripts/job-board.mjs`: once per run, `contract` (cached for the process); with contract ≥ 2,
  pass `--worktree` through for `job-start` (the skill's step 5 gives it); with an unknown
  higher contract, print one line ("board X needs a newer skill: git -C ~/ai-config pull") and
  carry on.
- `SKILL.md` "The board": shrink to the four facts it needs (call it through the shim; run
  `job-board.mjs guide` once per session and follow it; keep cards current; workers never add
  buttons or `answer`). The card-writing table moves to `guide` (and the README is generated from
  the same text). This also settles card 206's "point SKILL.md at the README" item.
- `hooks/job-guard.mjs`: block `answer` for workers and subagents, like `--option`.
- Step 5: `job-start <slug> --worktree <worktree> …`.
- `/job status`: `job-board.mjs ls` (mine) and one line from `ls --project all` counts.
- `mem-check.mjs` and `job-tabs.mjs`: no change for 0.5.0 (per repo, as today).

**Key binding and sidebar (card 207)**
- `board.mjs setup` reads Herdr's `config.toml` (the default session's `session_dir`, today
  `/root/.config/herdr/config.toml`, which has no keys and no sidebar rows), then:
  - copies it to `config.toml.bak-<YYYYMMDD-HHMMSS>` once per run that changes it;
  - key: if no `command = "herdr-job-board.open"` exists, appends the `[[keys.command]]` block
    with `prefix+b`, unless another `key = "prefix+b"` is in the file (then it stops and asks for
    `--key`);
  - sidebar: no `[ui.sidebar.spaces]` table: appends it with Herdr's two default rows plus
    `["$board"]`. A table that has `rows` without `"$board"`: inserts `["$board"],` before the
    array's closing `]` only when the array is the simple one-row-per-line shape; anything else
    is left alone and the lines to paste are printed;
  - runs `herdr server reload-config` (skip with `--no-reload`);
  - prints what changed; a second run prints `ok` for both and writes nothing (idempotent).
- `doctor`'s `add` lines for the key and the sidebar become one: `run board.mjs setup`.
- **What the sidebar shows**: each workspace reports **its own** cards (cards whose `workspace`
  is that workspace, plus cards of the project whose Herdr workspace label it is):
  `2 need you · 1 doing · 4 to do`. Each write recomputes the tokens of every workspace whose
  text changed (one `herdr workspace report-metadata` each, asynchronously) instead of only the
  writer's. The total goes in the board's title line, not the sidebar: the sidebar is per
  workspace already.

## 6. Telegram

- Facts: the Claude Telegram channel plugin polls the bot (`getUpdates`); polling is exclusive
  (`bot.pid`), so one bot feeds one Claude session. `claude-coordinator.sh` enables it for the
  coordinator session only for that reason. Sending (`tg-notify.sh`, `sendMessage`) works from
  any process at the same time. Only the allowlisted sender (one id in `access.json`) can write.
- **Option A, recommended: one bot, one front coordinator.**
  - Inbound: you reply `170 go`, `170 LON only first`, `170 2` or `204 keep as is`. The front
    coordinator runs `board.mjs answer 170 "LON only first" --from telegram`. A label matches a
    button case-insensitively (or by number, `2`); any other text up to 300 characters goes as
    free text. The board routes it (section 3): to the front itself when it owns the card (it
    then acts), to the owner pane otherwise. The front replies in Telegram with the board's one
    line: `sent to sfc coordinator (w4:p6)` or `no ai-config coordinator is running; take it
    myself?`.
  - Outbound (opt-in): a `notify` command in `~/.local/state/herdr-job-board/config.json`
    (`{"notify": ["/root/ai-config/scripts/tg-notify.sh"]}`), run with one argument (no shell)
    when a card enters Waiting with buttons: `🔔 170 sfc · magicwan v343 fleet rollout: approve
    the waves · Go / LON only first / Not today · reply "170 go"`. Title, ask's first line and
    labels only, never the description (it goes to an outside service). Off by default.
  - Coordinator gone: the front gets the answer only after it asks you (as the second press).
- **Option B: one bot per coordinator.** N bots from BotFather, N chats on the phone, N tokens;
  the channel plugin keeps its state in one folder (`~/.claude/channels/telegram/`) and every
  session that loads it takes over `bot.pid`, so it would need per-session state folders the
  plugin may not support. More moving parts for the same result. Not recommended.
